# macOS and iOS migration

**Status:** 2026-11-09. macOS desktop is source-complete and verified on this host. iOS is at
**M1: the app builds for the simulator and for a physical iPhone, is signed with a Personal Team,
and launches on the device**. No vault has been created on iOS and no message has crossed the relay
from it. TestFlight, Tor, and the remaining slices are not started.

The Android plan in [`MOBILE_APP_PLAN.md`](../MOBILE_APP_PLAN.md) remains the product source of
truth for what the phone does. This document records what changed to move the work to macOS and
add iOS, and what is still open.

## What was verified on this host

macOS 27 (arm64), Xcode 27.2, iOS 27.2 simulators, Rust 1.99.1.

| Check | Result |
|---|---|
| `cargo check --workspace` | passes |
| `cargo test -p hush-tauri` | 24 passed, 1 ignored (`needs a Tor binary and network`) |
| `npm test` in `apps/hush-tauri` | 311 passed |
| `./scripts/stage-daemon-sidecar.sh` | stages `hush-daemon-aarch64-apple-darwin` |
| `cargo check -p hush-tauri --target aarch64-apple-ios-sim` | passes |

| `xcrun devicectl device process launch --device <iphone> com.hush.capsule` | launches on the iPhone 13 (Personal Team, 7-day profile) |

The simulator run was checked visually: the Welcome card asks for vault name, nickname, and
passphrase, with no desktop rail. That is the same first-run surface the Android M1 verified.

## Toolchain this host needed

Installed user-locally; nothing in the repository depends on Homebrew paths.

```
rustup (stable, aarch64-apple-darwin)
rustup target add aarch64-apple-ios aarch64-apple-ios-sim x86_64-apple-ios
rustup component add llvm-tools
brew install bash protobuf xcodegen cocoapods
```

bash 4.4+ is required by the run and smoke scripts; macOS ships 3.2, and the
scripts' `#!/usr/bin/env bash` finds Homebrew's copy when `/opt/homebrew/bin` is
on PATH.

`llvm-tools` is not optional for iOS: without it swift-rs cannot externalize Tauri's `@_cdecl`
Swift symbols, and the Xcode link fails on `_log_stdout`, `_on_webview_created`, and
`_run_plugin_command`.

## Changes landed

### Build and platform

- **`Cargo.toml`**: pins nix to the upstream commit that fixes its iOS build. nix 0.31.3 gates
  `UtunIfname`/`KextControl` on `apple_targets` (which includes iOS) but `libc` defines
  `SYSPROTO_CONTROL` and `UTUN_OPT_IFNAME` only on macOS. `rtc-shared` (through webrtc) pulls it,
  so no iOS build works without this. Remove the patch when nix 0.31.4 is published.
- **`tauri.ios.conf.json`**: empty `externalBin` and `resources`. iOS has no daemon child and no
  Tor sidecar.
- **`tauri.macos.conf.json`**: empty `resources`. Stops the macOS bundle carrying the Linux Tor
  ELF and `libevent-2.1.so.7`, which closes the long-standing OPEN entry about a Linux ELF inside
  the macOS bundle. macOS uses the system Tor or `HUSH_TOR_BIN`, as `RELEASING.md` already says.
- **`gen/apple/`**: generated by `npx tauri ios init`. `project.yml` adds
  `NSMicrophoneUsageDescription`, `NSCameraUsageDescription`, `NSLocalNetworkUsageDescription`,
  and links `AudioToolbox` and `CoreAudio` (cpal and the native voice plane need both). Its
  `.gitignore` keeps 367 MB of `build/` and `Externals/` out of the tree.

### Scripts

- `stage-daemon-sidecar.sh`: `realpath --relative-to` is GNU-only; BSD `realpath` rejects it.
  Replaced with a prefix strip.
- `run-one-ui.sh` and `run-two-ui.sh`: the bundled Tor is a Linux ELF, so it is selected only on
  Linux; `HUSH_TOR_BIN` and the system copy are used on macOS. The loader variable is
  `DYLD_LIBRARY_PATH` on macOS.
- `run-one-ui.sh`: `wait -n` is bash 4.3+ and macOS ships bash 3.2. It now waits on the window.
- `run-two-ui.sh`: same problem; it polls its child PIDs instead.
- `smoke-change-passphrase.sh`: uses `shasum -a 256` when `sha256sum` is absent.

### Tests

- `daemon_client.rs` and `daemon_supervisor.rs` tests now create their scratch sockets under
  `/tmp`. A Unix socket path is capped at `SUN_LEN` (104 bytes on macOS), and the per-user
  `TMPDIR` (`/var/folders/...`) is long enough that three tests failed with
  `path must be shorter than SUN_LEN`.

## Open decisions before shipping iOS

1. **Signing and distribution.** A Personal Team signs 7-day device builds, and the iPhone 13 build
   uses one. TestFlight or the App Store needs a paid team, a distribution certificate, and a
   privacy manifest. Decide which path to take. A device build writes the chosen
   `DEVELOPMENT_TEAM` into `gen/apple/hush-tauri.xcodeproj/project.pbxproj`; that is local account
   state, so regenerate with `xcodegen generate` (or revert the line) before committing.
2. **Tor.** iOS forbids launching a `tor` child process, so the desktop and Android paths do not
   port. The relay defaults to HTTPS, so ordinary messaging works; Tor relay mode and the wallet's
   Tor binding do not. The Android plan's options apply: no Tor in v1 with a clear state, Orbot
   (not available on iOS), or embedded Arti. Decide before exposing the relay switch on iOS.
3. **Backup exclusion — done (2026-11-09).** `exclude_vault_from_icloud_backup` in
   `apps/hush-tauri/src-tauri/src/lib.rs` sets `NSURLIsExcludedFromBackupKey` on the vault
   directory at startup, so the container's automatic iCloud backup does not carry the keys.
   Verified on the simulator: `xattr -l` on the container's `.../vault` reports
   `com.apple.metadata:com_apple_backup_excludeItem: com.apple.MobileBackup`.
4. **Calls.** 1:1 signalling is platform-neutral; media is expected to use WKWebView WebRTC, as
   the Android plan says for the phone. The microphone usage string is present, but no call has
   been placed from iOS. Background audio and the no-push limitation still need a product
   decision.
5. **External links.** `hush_open_url` uses the `open` crate. Its iOS behaviour is unverified; if
   it is unsupported, move this command to `tauri-plugin-opener` or a UIKit call.
6. **CI.** The release workflow has macOS legs but no iOS job. A simulator build on a macOS runner
   is cheap and would catch the nix/Xcode drift; add it once signing is decided.

## Reproducing the iOS build

The system-wide `xcode-select` on this machine points at the Command Line Tools, and `sudo` is not
available non-interactively. Until it is changed with
`sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`, run the build with local
wrappers that pin `DEVELOPER_DIR`:

```sh
PATH="$PWD/.tools/bin:$HOME/.cargo/bin:/opt/homebrew/bin:$PATH" \
  npx tauri ios build --debug --target aarch64-sim --no-sign
```

`.tools/` is gitignored. The wrappers are a local workaround, not part of the product.
