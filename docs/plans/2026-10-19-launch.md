# Launch Implementation Plan

**Goal:** Ship Hush v1 as a public, paid release for Linux and macOS — a flat $1.99/month
subscription, issued as an offline-verifiable signed license that gates the relay and official
updates, while the vault and local history always open.

**Architecture:** A license is a signed document `{account_id, plan, issued_at, not_after, serial}`
verified offline against a public key compiled into the app and configured on the relay. The relay
verifies it statelessly on its write routes, so it stores no list of payers. A small `hush-license`
service beside the relay talks to Stripe, mints a license per billing period, and serves a renewal
pull authenticated by the vault's own key. The shared verifier lives in a new `hush-verify` crate
(DR-11), used by the app, the daemon and the relay.

**Tech Stack:** Rust (ed25519 signatures, axum 0.8, tokio 1, rusqlite), Tauri 2, Stripe Checkout +
Billing webhooks, Astro (marketing site, separate repo `HushWebsite`).

**Spec:** This conversation (launch scope: public paid v1, Linux + macOS, Stripe live, $1.99/month,
offline-signed license gating the connected experience); `docs/DESIGN.md` § Payments;
`docs/THREAT_MODEL.md` § Trust; `docs/plans/2026-10-04-v1-milestones.md` Task 7 and Task 8.

## Global Constraints

Verbatim, from `docs/DESIGN.md` § Payments and the decisions taken in this conversation:

- "Subscription via a normal card processor (Stripe or similar) as the default."
- "What they pay for: First-party relay and official auto-update. Not the right to open their own
  files. **No first-party storage tier** (removed 2026-10-19)."
- "Unpaid / lapsed: Vault, history, and local encryption still work. QR add and direct/online paths
  still work. You may cut *your* relay and official auto-update. **Do not brick the capsule.**"
- "Anonymous payment: Later optional extra, not v1. Default payment **will** link money to a
  name/email; do not market the product as anonymous."
- Price is **flat $1.99/month** — no founding tier, no first-100 mechanic.
- License validation is **offline**: a signed license verified against a public key baked into the
  app. **No phone-home on launch.**
- The relay **must not store a list of payers**.

## The launch gate

Launch is done when all of these are true:

1. A new user can pay $1.99 at `https://hushrelay.space/`, receive a license, paste it into the app,
   and send a message through the production relay.
2. A vault with no license, or an expired one, opens normally, reads its own history, and reports
   *why* the relay is unavailable. It does not brick and does not crash.
3. An expired license stops relay writes and update checks within the grace window, with no payer
   list on the relay.
4. The live site states only things that are true of the shipped build, at version parity with the
   relay manifest.
5. Privacy Policy and Terms are live and linked.
6. macOS builds launch without a Gatekeeper refusal.
7. `cargo deny` and `cargo audit` run in CI against a pinned toolchain.

**Interfaces:**
- Produces: `License { account_id: String, plan: String, issued_at: u64, not_after: u64, serial: String }`
- Produces: `License::canonical_bytes(&self) -> Vec<u8>` — a stable, order-fixed encoding
- Produces: `verify_license(license: &License, signature: &[u8], pubkey: &[u8; 32]) -> Result<(), VerifyError>`
- Produces: `License::check_valid_at(&self, now: u64, account_id: &str) -> Result<(), VerifyError>`
- Produces: `encode_license(license: &License, signature: &[u8]) -> String` / `decode_license(&str) -> Result<(License, Vec<u8>)>`
- Produces: `sign_license(license: &License, signing_key: &SigningKey) -> Vec<u8>` — the minting half, kept beside the verifier so the two cannot drift on the wire format
- Produces: `check_encoded_license(text: &str, pubkey: &[u8; 32], account_id: &str, now: u64) -> Result<License, VerifyError>` — decode, verify and entitlement check in one call
- Consumes: nothing (leaf crate)

**Status: implemented 2026-10-19.** `cargo test -p hush-verify` → 14 passed;
`cargo clippy -p hush-verify --all-targets` clean. Not committed.

```rust

mod tests {
    use super::*;

    fn sample() -> License {
        License {
            account_id: "ab12".into(),
            plan: "hush-monthly".into(),
            issued_at: 1_700_000_000,
            not_after: 1_700_086_400,
            serial: "lic_0001".into(),
        }
    }

    #[test]
    fn round_trips_through_the_text_form() {
        let (lic, sig) = (sample(), vec![7u8; 64]);
        let encoded = encode_license(&lic, &sig);
        let (back, sig_back) = decode_license(&encoded).expect("decodes");
        assert_eq!(back, lic);
        assert_eq!(sig_back, sig);
    }

    #[test]
    fn canonical_bytes_are_stable() {
        assert_eq!(sample().canonical_bytes(), sample().canonical_bytes());
    }

    #[test]
    fn rejects_an_expired_license() {
        let err = sample().check_valid_at(1_700_086_401, "ab12").unwrap_err();
        assert_eq!(err, VerifyError::Expired);
    }

    #[test]
    fn rejects_a_license_bound_to_another_account() {
        let err = sample().check_valid_at(1_700_000_001, "ffff").unwrap_err();
        assert_eq!(err, VerifyError::WrongAccount);
    }
}
```

  `the_whole_check_refuses_a_resigned_license_from_an_unknown_key` fail with

- [x] **Step 3: Minimal implementation** — the `License` struct and a length-prefixed canonical

  `hush-lic-v1:<payload>:<signature>`. Expiry is inclusive of `not_after`, and a payload carrying
  trailing bytes is refused rather than ignored.

- [x] **Step 4: Run test — expect PASS.**

- [x] **Step 5: Add signature verification** — `verify_license` over `canonical_bytes` using

  signature over a mutated payload fails; a signature from a different key fails; a short signature
  is refused rather than panicking; garbage input is `Malformed` rather than a panic; and the

- [x] **Step 6: Run tests — expect PASS.** Done: 14 passed, clippy clean. **Not committed** — no

## WS-2: Relay enforcement

**Files:**
- Modify: `crates/hush-relay/src/config.rs` (add `license_pubkey: Option<[u8; 32]>`, `license_grace: Duration`)
- Create: `crates/hush-relay/src/license.rs`
- Modify: `crates/hush-relay/src/app.rs` (the route table near line 521)
- Test: `crates/hush-relay/tests/license_gate.rs`

**Interfaces:**
- Consumes: `hush_verify::{License, verify_license, decode_license}`
- Produces: an extractor that reads a license from the `X-Hush-License` header plus the request's
  `account_id`, and rejects with `403` on missing, expired, tampered or mis-bound licenses

Enforcement points are the write routes only, so a lapsed vault can still drain what it already has:

- `PUT /q/{queue_id}` — `put_blob`
- `POST /q/{queue_id}/drain/ack` — `ack_drain`
- `PUT /b/{queue_id}` — `put_bulletin`
- `POST /k/{account_id}` — `put_prekey_record`

Read and delete routes stay open. That is the "cut your relay, do not brick the capsule" rule
expressed in code: a lapsed user can always retrieve and delete their own queued ciphertext.

- [ ] **Step 1: Write the failing test** in `crates/hush-relay/tests/license_gate.rs` — build a relay
  with `license_pubkey` set, then assert: a `PUT /q/{id}` with no license is `403`; with a valid
  license bound to the right account is `2xx`; with an expired license is `403`; with a license
  bound to a different account is `403`; and a `GET` on the same queue with no license is still `2xx`.
- [ ] **Step 2: Run test — expect FAIL** — `cargo test -p hush-relay --test license_gate`
- [ ] **Step 3: Implement** the extractor and apply it to the four routes. When `license_pubkey` is
  `None` the gate is off and every route behaves exactly as today — that keeps every existing test
  and run script working untouched, and makes the change reversible by config.
- [ ] **Step 4: Run test — expect PASS**, plus the full existing suite: `cargo test -p hush-relay`
- [ ] **Step 5: Document the new config** in `docs/ops/relay-prod-vps.md` and add the key to the
  production Caddy/systemd env. Commit.

**Constraint check:** no new table, no payer list, no per-account state. The relay holds one public
key and compares nothing across requests. State this in the module doc comment, because it is the
property the threat model depends on.

**Interfaces:**
- Consumes: `hush_verify::License`, Stripe API
- Produces: `POST /stripe/webhook` — verifies the Stripe signature, then on
  `checkout.session.completed` and `invoice.paid` mints a license for the `account_id` carried in

- Produces: `POST /license/renew` — body `{account_id, nonce, signature}`, verified against
  `account_id`; returns a fresh license when the subscription is active

**Store:** one table, `licenses(stripe_customer_id, account_id, serial, not_after, revoked)`. This
is the only place payment identity and vault identity meet. See "Decisions taken" below.

**Honest limits to record in `docs/THREAT_MODEL.md`:**

  Stripe customer ID" must be rewritten to say precisely that.

## Decisions taken (2026-10-19)

1. **Price is flat $1.99/month.** No founding tier and no first-100 mechanic. `CtaBand.astro`,
   `PRICING` in `HushWebsite/src/config.ts`, the FAQ answer in `Faq.astro:31` and the
   `AggregateOffer` JSON-LD in `index.astro:31-33` all encode the two-tier shape and are flattened
   in WS-5.
2. **The license binds to `account_id`** — the WS-1 design as written. One subscription cannot be
   shared between vaults. The cost is accepted and must be stated plainly rather than glossed:
   `hush-license` holds a Stripe customer id beside an `account_id`, so that service is the one
   place the two meet. The relay holds neither. `docs/THREAT_MODEL.md`'s line "the messenger
   identity is not the Stripe customer ID" is rewritten in WS-4 to say exactly this instead of the
   stronger claim it currently makes.
3. **The name is settled.** No rename. The product is **Hush**, the origin is `hushrelay.space`.
   The `hushline.app` collision noted in `HushWebsite/src/config.ts` on 2026-10-15 is accepted, and
   the site footer's "Working name — subject to change before launch" line is deleted in WS-5.
4. **First-party storage is out.** It was never built, and it is removed from what the subscription
   pays for — `docs/DESIGN.md` § Payments now lists the relay and official updates only, and the
   license gates those two. The bring-your-own cloud replica over WebDAV/S3 (still Task 8) is
   unaffected: that is the user's own storage, not ours. The site carries no first-party storage
   claim, so nothing there changes.
